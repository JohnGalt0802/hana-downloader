## 一、P0 目标（一句话）

把聊天流卡片的**内容生成**从 `ui/card.js` 里写死的 `render()`，抽成**由主题数据驱动的纯函数**；`minimal` 主题下的渲染输出必须与今日 `main` **完全一致**。

P0 **不做**：detail 主题的调参打磨、管理器预览列表 UI（属 P1）。P0 只做地基。

## 二、接口定义（主脑定，子代理不得改）

### 2.1 `ui/shared/theme.js`（数据层）

```js
// 主题原始定义（theme.json 解析后）
// { id, name, description?, author?, version?, basedOn?,
//   layout: {...}, palette?: {light:{},dark:{}}, metrics?: {...} }

/** 合并继承：把 raw 与其 basedOn 链逐层合并，返回完整主题对象（未覆盖字段落默认值）。 */
export function resolveTheme(raw, allRawThemes) -> Theme

/** 校验一份 theme.json。返回 { ok: boolean, errors: string[] } */
export function validateTheme(raw) -> { ok, errors }

/** 从 index.json 数组取清单（供管理器枚举）。 */
export function listThemes(indexEntries) -> Array<{id,name,description,author}>

export const DEFAULT_THEME_ID = "minimal";

/** 合并规则：对象深合并；数组整体替换；id/name/description/author/version 不继承。 */
```

**解析后的 Theme 对象形态**（`resolveTheme` 的返回，也是 `cardview` 的输入）：

```js
{
  id, name, description, author, version,
  layout: {
    fold, icon, primary, fields, fieldSep,
    progress, progressWhenDone, density, actions
  },
  palette: { light: { text, muted, accent, green, danger, warn, track, surface }, dark: { ... } },
  metrics: { width, radius, padding, gap, fontSize }
}
```

**默认值**（`resolveTheme` 必须填满，不允许 undefined）：以 `minimal` 主题的取值为准（见 `ui/themes/minimal/theme.json`）。

### 2.2 `ui/shared/cardview.js`（渲染层，纯函数）

```js
/**
 * 生成 #dl-root 内部 HTML。
 * 纯函数：不碰 DOM、不碰 hana.*、不读全局状态 —— 可 Node 侧 import 测试。
 * @param {object} task   任务快照（引擎 /wait 返回的 task）
 * @param {object} theme  resolveTheme 的返回
 * @param {object} opts   { expanded?: boolean, allExpanded?: boolean, retrying?: boolean, taskId?: string }
 * @returns {string}
 */
export function renderCardHTML(task, theme, opts) -> string
```

**约束**：
- 复用 `ui/shared/display.js` 的 `STAGE_TEXT / unitSuffix / isPkgTask / isCountTask`（唯一来源，不得另存一份）
- `minimal` 主题下的输出必须与今日 `main` 的 `render()` 逐字节一致（验收基准）

## 四、必须原样保留的行为（防回归清单，W3 必守）

见方案第十二节。摘要：

- 尺寸上报：`reportSize` + 宽度探查窗口 + `bootSettle` + `onReshow` + `ResizeObserver`
- 任务绑定：`bindTask`（`/engine/bind` 按 `cardInstanceId`）
- 状态机：`poll`/`schedule`（活跃 300ms、终态 5s 慢查）+ 任务丢失保留最后快照 + `lostNotified`
- 重试：`retry`（转圈）+ `/retry` 走 App 路由
- 动作：`cancel` / `reveal(mode)` / `copyPath` / `flashBtn`
- 折叠：`expanded`/`allExpanded`/`applyExpandState`/`toggleFold`/`toggleAll` + `setAll` 广播
- 事件委托：模块级唯一监听
- 主题同步：`syncTheme`（宿主明暗跟随）
- 广播：`hana-dl-cards` 通道

## 五、验收标准（硬）

1. **回归无损**：`minimal` 主题下，`renderCardHTML(t, minimal, opts)` 对**验收基准集**的输出，与基准 HTML **完全一致**（基准见 `tests/fixtures/cardview-golden.json`）。
2. **单测通过**：`node tests/run-tests.mjs` 全绿；新增 `tests/unit-cardview.mjs` 覆盖各状态分支。
3. **真机**：在真实会话里跑一笔下载，卡片显示与现状无差异（P0 阶段不切主题）。

## 六、风险

| 风险 | 缓解 |
|---|---|
| 抽纯函数时漏掉某个状态分支 | 验收基准集覆盖全部状态形态；逐字节比对 |
| 主题默认值与现状不一致 | `minimal/theme.json` 由现状反推；基准比对兜底 |
| W3 改 card.js 碰坏尺寸自愈 | 保留清单逐条核对；真机验证切会话不变形 |
