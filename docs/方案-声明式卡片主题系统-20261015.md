# 方案：声明式卡片主题系统

**项目**：hana-downloader（小花下载器 v2 App）
**日期**：2026-10-15
**状态**：方案待 John 过目，未开工
**决策依据**：John 2026-10-15 定档（B 档声明式 / 先出规范 / 主题目录建在本仓库）

---

## 一、背景与目标

PR#4 带来一套与现有卡片取向不同的实现：去掉折叠与详情面板，改为信息常驻（格式徽章 + 文件名 + 状态标签 + 副行）。现有那套则是默认收起、点开看详情。

John 的判断是不二选一：**两套都留，并开口子让第三方也能提主题**。

本方案要解决的问题是：怎么让"卡片长什么样"变成**可被第三方提交的数据**，而不是必须由我们改代码。

**目标**：
1. 卡片外观可由一份声明式配置文件完整描述；
2. 用户可在管理器里切换主题；
3. 第三方可通过向本仓库提 PR 贡献主题，审核成本低（读一份 JSON 即可）；
4. 现有行为（轮询、绑定、尺寸自愈、reveal 分流等）不受主题影响。

---

## 二、核心决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | **主题 = 数据，不是代码** | 若主题能带任意 JS，每个主题都等于收一份可执行代码，审核责任与风险都不合理 |
| 2 | **一套 DOM 结构，主题只调参数** | 两套并行 DOM 会导致双份维护，撞项目铁律（同主题改动一次改完） |
| 3 | **主题集合随 App 包走** | `ui/` 是装载时拍下的不可变快照（Hana 0.1028.0 起），主题文件必须随包分发 |
| 4 | **选中项是用户设置** | 存 `engine-config.json`，走现有 `/settings` 透传，引擎零改动 |
| 5 | **核心信息不可被主题隐藏** | 状态与失败原因是卡片的功能底线，主题无权关闭 |

---

## 三、主题模型

主题分三层，覆盖不同维度，互不干扰：

```
theme.json
├── layout    结构层：显示什么、怎么排、要不要折叠
├── palette   样式层：明暗两套色彩 token
└── metrics   尺寸层：卡片宽度、圆角、间距、字号
```

三层正交。**结构层是决定性的**（两套卡片的真正差异在这里，不在配色），样式与尺寸层才是传统意义上的"换肤"。

## 四、theme.json 规范

### 4.1 完整示例（对应 PR#4 那套）

```json
{
  "id": "detail",
  "name": "详细",
  "description": "信息常驻，一眼看全；适合文件管理场景",
  "author": "onceblue59",
  "version": 1,
  "basedOn": "minimal",

  "layout": {
    "fold": false,
    "icon": "badge",
    "primary": "name",
    "fields": ["size", "speed", "eta", "host"],
    "fieldSep": " · ",
    "progress": "row",
    "progressWhenDone": false,
    "density": "comfortable",
    "actions": {
      "done": ["open", "folder"],
      "failed": ["retry"],
      "active": ["cancel"]
    }
  },

  "metrics": {
    "width": 560,
    "radius": 9,
    "padding": "12px 14px",
    "gap": 12,
    "fontSize": 12
  }
}
```

### 4.2 字段说明

**顶层**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 主题唯一标识，kebab-case，本包内唯一 |
| `name` | string | ✅ | 显示名（管理器里给用户看） |
| `description` | string | | 一句话说明 |
| `author` | string | | 贡献者（GitHub 名） |
| `version` | number | | 主题自身版本，从 1 起 |
| `basedOn` | string | | 基线主题 id，继承其未覆盖的字段 |

**layout（结构层）**

| 字段 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `fold` | `true` / `false` | `true` | 是否启用折叠 + 详情面板 |
| `icon` | `"badge"` / `"dot"` / `"none"` | `"dot"` | 左侧图标形态：`badge` = 40×40 格式徽章（图标 + 扩展名）；`dot` = 小状态徽章；`none` = 不显示 |
| `primary` | `"name"` / `"badge"` | `"badge"` | 主行首元素：`name` = 文件名当主实体；`badge` = 状态徽章打头 |
| `fields` | string[] | 见下 | 副行显示的附加字段，从**可选字段集**里选，可调顺序 |
| `fieldSep` | string | `" · "` | 字段间分隔符 |
| `progress` | `"row"` / `"inline"` / `"none"` | `"row"` | 进度条位置：独占一行 / 与信息同行 / 不显示 |
| `progressWhenDone` | boolean | `true` | 完成态是否保留进度条 |
| `density` | `"compact"` / `"comfortable"` | `"compact"` | 间距与字号档 |
| `actions` | object | 见下 | 各状态下显示哪些动作按钮 |

**可选字段集**（`fields` 的取值）：

| 值 | 含义 | 典型出现时机 |
|---|---|---|
| `size` | 体积 / 计数（已下载 / 总量） | 下载中、完成 |
| `speed` | 速度 | 下载中 |
| `eta` | 剩余时间 | 下载中 |
| `stage` | 阶段（解析依赖 / 校验哈希…） | 命令型任务 |
| `host` | 来源主机名 | 排队、完成 |
| `note` | 任务备注 | 完成 |
| `error` | 失败原因 | 失败、取消、中断 |

**核心字段（不可关闭）**：`state`（状态）与 `error`（失败原因）由核心固定渲染，**主题的 `fields` 不能移除它们**。理由见第七节。

**actions 取值**：`open`（打开文件）、`folder`（打开文件夹）、`cancel`（取消）、`retry`（重试）、`copy`（复制路径，仅折叠式详情面板内）。主题只能从各状态的**允许集合**里挑选，不能新增动作（动作行为由核心实现，主题无权定义）。

**palette（样式层）**

`palette.light` 与 `palette.dark` 各为一组 token，卡片按宿主明暗自动选一套：

| token | 说明 |
|---|---|
| `text` | 主文字 |
| `muted` | 次要文字 |
| `accent` | 强调色（下载中、主按钮） |
| `green` | 成功 |
| `danger` | 失败 |
| `warn` | 停滞 / 警告 |
| `track` | 进度条槽 / 边框 |
| `surface` | 徽章底、按钮 hover 底 |

未给的 token 继承基线。**不允许任意 CSS 选择器**：主题只能改 token 值，不能写 `position: fixed` 之类的规则。

**metrics（尺寸层）**

| 字段 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `width` | number | `400` | clamp 到 `[320, 720]`（宿主信封上限 774） |
| `radius` | number | `9` | 卡片外层圆角（px） |
| `padding` | string | `"12px 14px"` | CSS 内边距 |
| `gap` | number | `12` | 主元素间距（px） |
| `fontSize` | number | `12` | 根字号（px） |

## 五、可调字段清单（对照两套现有实现）

| 维度 | 极简（现有，`minimal`） | 详细（PR#4，`detail`） |
|---|---|---|
| `fold` | `true`（有折叠 + 详情表） | `false` |
| `icon` | `dot`（小状态徽章） | `badge`（40×40 格式徽章） |
| `primary` | `badge`（状态徽章打头） | `name`（文件名当主实体） |
| `fields` | `["eta","stage","note"]` | `["size","speed","eta","host"]` |
| `progress` | `row`（+ 完成态绿条） | `row` |
| `progressWhenDone` | `true` | `false` |
| `density` | `compact` | `comfortable` |
| `metrics.width` | `400` | `560` |

**结论：上表八行差异，全部可由 `layout` + `metrics` 表达，不需要任何代码。** 这验证了 B 档声明的表达力足够覆盖 PR#4。

## 六、合并与继承

1. 主题可声明 `basedOn: "<基线 id>"`，未覆盖的字段从基线取；
2. 合并规则：**对象深合并，数组整体替换**（`fields` 不逐个合并，避免顺序歧义）；
3. `id` / `name` / `description` / `author` / `version` 不从基线继承；
4. 基线必须存在，否则该主题加载失败并回落到内置默认；
5. 内置基线 `minimal` 不声明 `basedOn`。

继承的价值：`detail` 只写 `layout` + `metrics.width`，配色与其余尺寸全从 `minimal` 拿，避免每个主题重复抄一遍色板。

## 七、边界与安全

### 7.1 主题禁止做的事

| 禁止项 | 原因 |
|---|---|
| 含可执行代码（JS、内联事件、`<script>`） | 主题是数据，不是代码 |
| 引用外部网络资源 | 卡片 iframe 受 CSP 与清单白名单约束，且引入不可控内容 |
| 改变行为（轮询节奏、绑定逻辑、状态机、下载逻辑） | 主题只影响"怎么画"，不影响"怎么动" |
| 隐藏核心信息（状态、失败原因） | 卡片的功能底线 |
| 覆写尺寸上报机制 | 尺寸自愈（宽度探查窗口）固定在核心，主题不可干预 |
| 写任意 CSS 规则 | 只允许改 token 值 |
| 卡片宽度越过信封上限 | clamp 保护 |

### 7.2 审核清单（每份主题 PR 照此逐条过）

1. JSON 能否通过 `theme.schema.json` 校验；
2. 有无未知字段（未知字段一律拒收，不静默忽略）；
3. 有无外部 URL；
4. token 值格式是否合法（颜色 / 长度）；
5. `fields` 是否只从可选集取；
6. `actions` 是否只从允许集取；
7. `width` 是否越界。

全部为机械检查，**审一个主题 = 读一份 JSON**，这是选 B 档的核心理由。

## 八、加载与生效链路

```
① 打包：ui/themes/<id>/theme.json 随 App 包走（受 ui/ 快照约束）
② 枚举：ui/themes/index.json 列出全部主题（id / name / description）
③ 选择：管理器齿轮菜单 → 读到列表 → 用户点选
④ 存储：POST /settings { cardSkin: "<id>" } → engine-config.json（透传，引擎零改动）
⑤ 读取：卡片启动时 GET /engine/settings 取 cardSkin
⑥ 渲染：卡片按主题的 layout/palette/metrics 生成 DOM
⑦ 即时：切换时向 hana-dl-cards 通道广播 { type: "skinChanged" } → 在屏卡片重绘
```

### 关键约束（必须知道）

**`ui/` 是装载时拍下的不可变快照。** 主题文件随 App 版本走，**新增主题要发版 + 用户更新 App 才生效**，不是改完磁盘文件就即时可见。

这与"提 PR 即生效"不同，但与市场的分发形态一致：市场也是打包 + 发版这条链。合入 PR 后，主题随下个版本发布。

## 九、目录结构与投稿流程

```
ui/themes/
├── index.json            # 主题清单（管理器枚举用）
├── schema/
│   └── theme.schema.json # 校验规范
├── minimal/
│   └── theme.json        # 内置基线（现有那套）
└── detail/
    └── theme.json        # 内置第二个（PR#4 那套）
```

**投稿流程**（写进 `docs/主题投稿指南.md`）：

1. Fork 本仓库；
2. 新建 `ui/themes/<你的主题 id>/theme.json`；
3. 在本机改 `ui/themes/index.json` 加上你的条目；
4. 提 PR，正文写明主题取向与截图；
5. 维护者按 7.2 清单审核，通过后随下个版本发布。

## 十一、决策记录（John 2026-10-15 定）

| # | 事项 | 决定 |
|---|---|---|
| 1 | 主题是否允许携带 CSS token 之外的资源 | **允许内联 SVG**（图标等），**禁止外部文件与网络图**；内联 SVG 可随主题 JSON 携带或走 data URI |
| 2 | 管理器里主题选择的呈现形态 | **带预览的列表**（列表项展示该主题的真实渲染预览 + 名称 + 作者） |
| 3 | 新装用户默认主题 | **极简（`minimal`）**，即现有那套；detailed 作为可选项 |

仍待定（不阻塞 P0）：

4. **主题 id 命名空间**：倾向不加作者前缀，id 在本包内唯一即可；`index.json` 记 `author`，冲突由维护者协调。
5. **预览形态**（P1 决策）：倾向用**真实渲染的小尺寸活预览**（同一份典型任务数据渲染该主题），而非静态 `thumb.png`——避免维护两套、且所见即所得。若成本过高再退回静态缩略图。

## 十二、P0 施工边界（防回归）

P0 只改"怎么画"，绝不动"怎么动"。必须原样保留的行为清单：

**保留（不碰）**：
- 尺寸上报：`reportSize` + 宽度探查窗口 + `bootSettle` + `onReshow` + `ResizeObserver`
- 任务绑定：`bindTask`（`/engine/bind` 按 `cardInstanceId` 认领）
- 状态机：`poll` / `schedule`（活跃 300ms、终态 5s 慢查）+ 任务丢失保留最后快照 + `lostNotified`
- 重试：`retry`（转圈直到状态翻身）+ `/retry` 走 App 路由
- 动作：`cancel` / `reveal(mode)` / `copyPath`
- 折叠状态与联动：`expanded` / `allExpanded` / `applyExpandState` / `toggleFold` / `toggleAll` + `setAll` 广播（卡片间同步）
- 事件委托：模块级唯一监听
- 主题同步：`syncTheme`（宿主明暗跟随）
- 广播：`hana-dl-cards` 通道

**改造（仅这一层）**：
- `render()` 的内容生成 → 抽为 `ui/shared/cardview.js` 的纯函数 `renderCardHTML(task, theme, opts)`
- 渲染用到的配色/尺寸/结构，全部改为从主题数据读取

**回归验收（硬标准）**：
用同一批任务数据，在 `minimal` 主题下渲染，输出应与今日 `main` 完全一致（逐字节或逐节点比对）。
