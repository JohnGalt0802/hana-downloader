## 二、与方案的两处偏离（都是实测后改的）

### 2.1 接口从十组变十三组

方案 §3.2 定了十组。实施中发现了三个**必须**进层的：

| 新增 | 为什么不能留在业务层 |
|---|---|
| `nullDevice()` | `curl -o NUL` vs `/dev/null`。原来写在 `probeDirect` 里做三元判断，与 `spawnOpts`/`killTree` 是同一类事实（平台差异），留在外面就多一个「忘改」的位置 |
| `pidAlive(pid)` | 收孤儿命令要用。`process.kill(pid, 0)` 在 win 上行为与 posix 有差异（EPERM 语义），散在业务层就只能靠注释提醒 |
| `processNameOf(pid)` | 收孤儿的安全阀（防 PID 复用误杀）。win 靠 `tasklist /FO CSV`，posix 靠 `ps -o comm=`，是纯平台知识 |

### 2.2 `spawnOpts` 只用于 `spawn`，不用于 `spawnSync`

`spawnOpts` 的 posix 实现带 `detached: true`。`spawnSync` 也接受 `detached`，但语义完全不同（同步调用根本不存在「脱离」这件事，反而可能影响子进程的会话归属）。所以 `spawnSync` 处只用 `platform.name === "win32"` 决定 `windowsHide`，不套 `spawnOpts`。

**这是有意的例外，不是漏改。**

## 四、`detached` 的代价与收尾（方案 §7.2 的对称问题）

给 posix 子进程加 `detached` 解决了「取消能杀掉整棵树」，但引入了新问题：

> **引擎被 SIGKILL 时，子进程不会跟着死。** 它会变成真正的孤儿，继续写同一个目录，而 App 侧已经把它标成「已中断」。

这不是理论风险，是同一个机制的另一面。收尾分两步：

1. **落盘 pid**：`_persist()` 写 `childPid`（仅 `kind=command && state=running` 时），终态自动清空
2. **restore 收孤儿**：`_reapOrphanCommand(pid, cmdType)` 先 `pidAlive` 探活、再 `processNameOf` 核名（防 PID 复用误杀），两者都对才 `killTree`

**核名这一步不能省。** 引擎停机一小时后，那个 pid 可能已经属于用户的别的程序；只凭 pid 杀就是拿用户的系统赌运气。拿不到进程名时**宁可不动**——误杀代价远大于漏杀。

## 五、能力裁剪的三个决定

### 5.1 proxyControl：非 Windows 关闭，且入口**消失**不是灰掉

那套东西的形态完全是 Windows 的：读注册表、扫 `C:\Program Files` 找 `.exe`、`tasklist` 查进程、`taskkill` 杀。mac 用户的梯子习惯（ClashX / mihomo / sing-box）差得远，搬过去也不对味。

**回包选择 200 + `unsupported:true` 而不是 4xx**：这不是「你请求错了」，是「本机没有这个能力」。UI 拿到 `unsupported` 就该把入口拿掉，而不是弹一个错。

灰掉的按钮会让人反复点、以为是 bug；消失是真话。

### 5.2 winget：不注册，而不是注册了再报错

`download-command` 的 `kind` enum 由能力表生成：非 Windows 上根本没有 `winget-install` 这一项。模型看不到就不会去调。

同时 `execute` 里再拦一道——模型可能无视 enum 硬传，也可能换了平台后旧调用缓存还在。这一道的文案必须给出**可用的替代**（`git-clone / pnpm-install / pip-install`），而不是只说「不行」。

**一个例外**：`HAS_WINGET` 的判断是 `platform.name === "win32" || capabilities.pkgManager === "winget"`。为什么不是纯能力探测——能力探测的负结果只缓存 5 秒（为「装完即用」），而工具的 enum 在 App 启动时就定下来了。若启动那一刻恰好探测失败（进程刚起、PATH 未就绪），winget 会被永久剔出 enum 直到重启。用平台结构条件兜住这一格。

### 5.3 PEP 668：给出路，不给「绕过」

Debian/Ubuntu 24.04、Homebrew Python 把系统 Python 标成 `externally-managed`，pip 直接拒装。

**明确不给 `--break-system-packages`**：那会把系统 Python 的包管理搞坏，而且用户看不见这种持久损坏。文案直接指向 venv（`python -m venv .venv` + `pythonPath` 指过去）或 `runner="uv"`。

这条有断言盯着：参数数组里出现 `--break-system-packages` 即失败。

## 六、测试层面的两条教训

### 6.1 断言不要押注「机器干净」

`macos-13` / `ubuntu-latest` 这些 runner 上，Git for Windows 之类会把 `which` 放进 PATH。原断言写的是「本机没有 which 命令 → darwin.which 必须返回空」，在 runner 上直接红。

**改法**：押注契约而不是押注环境——「不抛、返回字符串、要么空要么指向真实存在的路径」。这个版本在本机和 CI 上都成立，而且验的仍是那件真正重要的事。

### 6.2 「测试全绿」不等于「路径走对了」

`unit-processtree.mjs` 里有一条**真起父子孙三层进程**的用例：父进程 spawn 子进程写心跳文件，然后断言 `killTree` 之后心跳**真的停了**。

只断言「killTree 返回 true」是不够的——旧代码的 `child.kill()` 也返回 true，但只杀组长。心跳文件是唯一能证明「孙进程真的死了」的东西。

## 九、独立审查（2026-10-20，三份并行）

主脑自审闭环被指出后，派了三份独立审查（laoge），各自范围独立、目标文件不重叠：

| 审查 | 范围 | 主要结论 |
|---|---|---|
| A | 进程树机制（spawnOpts/killTree/孤儿收尾） | Windows 侧可用；**posix 侧的孤儿收尾不能算可靠**，4 条静默失效路径 |
| B | 能力裁剪回归 | **Windows 行为完全未被改坏**（六端点实测等价）；但挖出三处裁剪遗漏与一个验收缺口 |
| C | 五个「顺手修」的缺陷 | 2 条对、1 条描述反了、2 条重心写错 |

### 9.1 A 的核心发现：我做的这套孤儿收尾，在主要平台上几乎不触发

**实测（本机 Windows）**：用四种方式起父进程（windowsHide / 可见控制台 / detached / Start-Process），
杀掉父进程后**子进程都在约 100ms 内消失**，pidAlive 立刻 false。
只有 `detached:true` 起的子进程活了下来。

也就是说，「引擎被硬杀、子进程继续写目录」这个前提在 Windows 上很难成立（控制台销毁连带终止）。
我专门加的 childPid 落盘 + _reapOrphanCommand 这套，在主要平台上基本空转。

**posix 侧的结构错误**（真问题）：

```
_reapOrphanCommand:  pidAlive(pid)   ← 探的是「组长」
                     killTree(pid) → kill(-pid)  ← 杀的是「进程组」
```

组长先死、组员还活着时，pidAlive 返回 false，函数直接 return ——
而 kill(-n) 本来还能把整组清掉。**探活和杀的对象不是同一个东西。**

其余漏口：reap 失败后 pid 照样被抹（restore() 没接返回值）、retry() 覆盖旧 pid、
核名挡不住 pid 复用（实测：对无关 node 进程调 killTree 返回 true，进程被杀）。

### 9.2 B 的核心发现：Windows 没被改坏，但裁得不够一致

六端点双引擎对照实测等价（唯一差异是 systemProxy 多了个 additive 的 source 字段）。
三处遗漏已修，详见 §3 第二张表。

**还指出一个验收缺口**：unit-capabilities.mjs 里关于这三块的断言全是**源码文本正则**
（「六个端点都带能力守卫」= 在 server.js 里搜字符串）。它只证明「守卫写在正确位置」，
**没证明「Windows 行为没变」**。这是这次最该记住的教训：

> **我的测试验证的是「我写了这段代码」，不是「这个功能在用户机器上对」。**

### 9.3 C 的核心发现：我把表层写成了主戏

第 4 条（findPnpmEntry）**描述就是错的**，旧代码本来就有兜底。已重写踩坑记录 #58。
第 5 条（readSystemProxy 两态）重心写错：真正的病灶是「旧代码无视 ProxyEnable」与
「多协议串静默直连」，一个被我顺手修好却没写、一个当时没碰。已按 5a/5b 重写。
